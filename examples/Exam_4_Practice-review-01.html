Walkthrough

Two-level paging requires two lookups: first in the Page Directory, then in a Page Table. The virtual address is split into three parts: PDI | PTI | Offset. Don't forget to pad with the appropriate number of 0s! Step 1: Extract components from Virtual Address Virtual Address = PDI | PTI | Offset 0b1111111101 = 0b111 | 0b111 | 0b1101 Step 2: Look up Page Directory Entry Using PDI = 0b111, we find PD Entry = 0b111010 Step 3: Check Page Directory Entry validity The MSB (valid bit) is 1, so this PD Entry is VALID. Step 4: Extract Page Table Number We remove the valid bit from the PD Entry to get the Page Table Number:
$$ \displaystyle \texttt{11010} = \texttt{0b111010} \& \texttt{0b011111} \; $$
This tells us to use Page Table #26. Step 5: Look up Page Table Entry Using PTI = 0b111 in Page Table #26, we find PTE = 0b100101 Step 6: Check Page Table Entry validity The MSB (valid bit) is 1, so this PTE is VALID. Step 7: Extract PFN We remove the valid bit from the PTE to get the PFN:
$$ \displaystyle \texttt{00101} = \texttt{0b100101} \& \texttt{0b011111} \; $$
Step 8: Construct Physical Address Physical Address = PFN | Offset
$$ \displaystyle \mathbf{\mathtt{0b001011101}} = \mathtt{0b00101} \mid \mathtt{0b1101} \; $$

This question accepts either AMAT convention. One convention uses a weighted average with hit rate and miss rate. The other uses hit time plus a miss-rate penalty term. If you use the weighted-average convention, compute:
$$ \displaystyle \begin{array}{l} AMAT = (\text{hit rate}) \cdot (\text{hit time}) + (\text{miss rate}) \cdot (\text{miss time}) \\ \phantom{AMAT} = (0.9956) \cdot (9) + (0.0044) \cdot (50000) = 228.9604\text{cycles} \\ \end{array} \; $$
If you use the miss-penalty convention, compute:
$$ \displaystyle \begin{array}{l} AMAT = \text{hit time} + (\text{miss rate}) \cdot (\text{miss time}) \\ \phantom{AMAT} = 9 + (0.0044) \cdot (50000) = 229.0000\text{cycles} \\ \end{array} \; $$

Walkthrough

If we are given an inode number, there are a few steps that we need to take to load the actual inode. These consist of determining the address of the inode, which block would contain it, and then its address within the block. To find the inode address, we calculate:
$$ \displaystyle (\text{Inode address}) = (\text{Inode Start Location}) + (\text{inode #}) \cdot (\text{inode size}) \; $$
$$ \displaystyle = 15360 + 209 \cdot 512 \; $$
$$ \displaystyle = 122368 \; $$
Next, we use this to figure out what block the inode is in. We do this directly so we know what block to load, thus minimizing the number of loads we have to make.
$$ \displaystyle \text{Block containing inode} = (\text{Inode address}) \text{//} (\text{block size}) \; $$
$$ \displaystyle = 122368 \text{//} 7680 \; $$
$$ \displaystyle = 15 \; $$
When we load this block, we now have in our system memory (remember, blocks on the hard drive are effectively useless to us until they're in main memory!), the inode, so next we need to figure out where it is within that block. This means that we'll need to find the offset into this block. We'll calculate this both as the offset in bytes and also in number of inodes, since we can use array indexing.
$$ \displaystyle \text{offset within block} = (\text{Inode address}) \text{ mod } (\text{block size}) \; $$
$$ \displaystyle = 122368 \text{ mod } 7680 \; $$
$$ \displaystyle = 7168 \; $$
Remember that mod is the same as %, the modulo operation.
$$ \displaystyle \text{index within block} = \frac{\text{offset within block}}{\text{inode size}} \; $$
$$ \displaystyle = \frac{7168}{512} \; $$
$$ \displaystyle = 14 \; $$

Walkthrough

To calculate the total disk access time (or "delay"), we should first calculate each of the individual parts. Since we know that:
$$ \displaystyle t_{total} = (\text{# of reads}) \cdot t_{access} + t_{transfer} \; $$
We therefore need to calculate \(t_{access}\) and \(t_{transfer}\) , where \(t_{access} = t_{rotation} + t_{seek}\) . Starting with the rotation delay, we calculate:
$$ \displaystyle t_{rotation} = \frac{1 \text{ minute}}{13500 \text{ revolutions}}\cdot \frac{60 \text{ seconds}}{1 \text{ minute}} \cdot \frac{1000 \text{ ms}}{1 \text{ second}} \cdot \frac{1 \text{ revolution}}{2} = 2.22ms \; $$
Now we can calculate:
$$ \displaystyle t_{access} = t_{rotation} + t_{seek} = 2.22ms + 17.00ms = 19.22ms \; $$
Next we need to calculate our transfer delay, \(t_{transfer}\) , which we do as:
$$ \displaystyle t_{transfer} = \frac{14 \cdot 4 \text{ KB}}{1} \cdot \frac{1 \text{ MB}}{1024 \text{ KB}} \cdot \frac{1 \text{ second}}{231 \text{ MB}} \cdot \frac{1000 \text{ ms}}{1 \text{ second}} = 0.24ms \; $$
Putting these together we get:
$$ \displaystyle t_{total} = \text{(# reads)} \cdot t_{access} + t_{transfer} = 14 \cdot 19.22 + 0.24 = 269.35ms \; $$
