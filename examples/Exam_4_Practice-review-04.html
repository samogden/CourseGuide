Walkthrough

Two-level paging requires two lookups: first in the Page Directory, then in a Page Table. The virtual address is split into three parts: PDI | PTI | Offset. Don't forget to pad with the appropriate number of 0s! Step 1: Extract components from Virtual Address Virtual Address = PDI | PTI | Offset 0b0100101100 = 0b010 | 0b010 | 0b1100 Step 2: Look up Page Directory Entry Using PDI = 0b010, we find PD Entry = 0b110101 Step 3: Check Page Directory Entry validity The MSB (valid bit) is 1, so this PD Entry is VALID. Step 4: Extract Page Table Number We remove the valid bit from the PD Entry to get the Page Table Number:
$$ \displaystyle \texttt{10101} = \texttt{0b110101} \& \texttt{0b011111} \; $$
This tells us to use Page Table #21. Step 5: Look up Page Table Entry Using PTI = 0b010 in Page Table #21, we find PTE = 0b111110 Step 6: Check Page Table Entry validity The MSB (valid bit) is 1, so this PTE is VALID. Step 7: Extract PFN We remove the valid bit from the PTE to get the PFN:
$$ \displaystyle \texttt{11110} = \texttt{0b111110} \& \texttt{0b011111} \; $$
Step 8: Construct Physical Address Physical Address = PFN | Offset
$$ \displaystyle \mathbf{\mathtt{0b111101100}} = \mathtt{0b11110} \mid \mathtt{0b1100} \; $$

Walkthrough

This question accepts either AMAT convention. One convention uses a weighted average with hit rate and miss rate. The other uses hit time plus a miss-rate penalty term. If you use the weighted-average convention, compute:
$$ \displaystyle \begin{array}{l} AMAT = (\text{hit rate}) \cdot (\text{hit time}) + (\text{miss rate}) \cdot (\text{miss time}) \\ \phantom{AMAT} = (0.9962) \cdot (7) + (0.0038) \cdot (10000) = 44.9734\text{cycles} \\ \end{array} \; $$
If you use the miss-penalty convention, compute:
$$ \displaystyle \begin{array}{l} AMAT = \text{hit time} + (\text{miss rate}) \cdot (\text{miss time}) \\ \phantom{AMAT} = 7 + (0.0038) \cdot (10000) = 45.0000\text{cycles} \\ \end{array} \; $$
If the table gives hit rate, use 1 - hit rate for miss rate. If it gives miss rate, use it directly.

To calculate the overall Turnaround and Response times using First In First Out we want to first start by calculating the respective target and response times of all of our individual jobs. We do this by subtracting arrival time from either the completion time or the start time. That is:
$$ \displaystyle Job_{TAT} = Job_{completion} - Job_{arrival\_time} \; $$

For each of our 4 jobs, we can make these calculations. Walkthrough

If we are given an inode number, there are a few steps that we need to take to load the actual inode. These consist of determining the address of the inode, which block would contain it, and then its address within the block. To find the inode address, we calculate:
$$ \displaystyle (\text{Inode address}) = (\text{Inode Start Location}) + (\text{inode #}) \cdot (\text{inode size}) \; $$
$$ \displaystyle = 2880 + 12 \cdot 64 \; $$
$$ \displaystyle = 3648 \; $$
Next, we use this to figure out what block the inode is in. We do this directly so we know what block to load, thus minimizing the number of loads we have to make.
$$ \displaystyle \text{Block containing inode} = (\text{Inode address}) \text{//} (\text{block size}) \; $$
$$ \displaystyle = 3648 \text{//} 576 \; $$
$$ \displaystyle = 6 \; $$
When we load this block, we now have in our system memory (remember, blocks on the hard drive are effectively useless to us until they're in main memory!), the inode, so next we need to figure out where it is within that block. This means that we'll need to find the offset into this block. We'll calculate this both as the offset in bytes and also in number of inodes, since we can use array indexing.
$$ \displaystyle \text{offset within block} = (\text{Inode address}) \text{ mod } (\text{block size}) \; $$
$$ \displaystyle = 3648 \text{ mod } 576 \; $$
$$ \displaystyle = 192 \; $$
Remember that mod is the same as %, the modulo operation.
$$ \displaystyle \text{index within block} = \frac{\text{offset within block}}{\text{inode size}} \; $$
$$ \displaystyle = \frac{192}{64} \; $$
$$ \displaystyle = 3 \; $$

Walkthrough

To calculate the total disk access time (or "delay"), we should first calculate each of the individual parts. Since we know that:
$$ \displaystyle t_{total} = (\text{# of reads}) \cdot t_{access} + t_{transfer} \; $$
We therefore need to calculate \(t_{access}\) and \(t_{transfer}\) , where \(t_{access} = t_{rotation} + t_{seek}\) . Starting with the rotation delay, we calculate:
$$ \displaystyle t_{rotation} = \frac{1 \text{ minute}}{12600 \text{ revolutions}}\cdot \frac{60 \text{ seconds}}{1 \text{ minute}} \cdot \frac{1000 \text{ ms}}{1 \text{ second}} \cdot \frac{1 \text{ revolution}}{2} = 2.38ms \; $$
Now we can calculate:
$$ \displaystyle t_{access} = t_{rotation} + t_{seek} = 2.38ms + 18.00ms = 20.38ms \; $$
Next we need to calculate our transfer delay, \(t_{transfer}\) , which we do as:
$$ \displaystyle t_{transfer} = \frac{2 \cdot 8 \text{ KB}}{1} \cdot \frac{1 \text{ MB}}{1024 \text{ KB}} \cdot \frac{1 \text{ second}}{168 \text{ MB}} \cdot \frac{1000 \text{ ms}}{1 \text{ second}} = 0.09ms \; $$
Putting these together we get:
$$ \displaystyle t_{total} = \text{(# reads)} \cdot t_{access} + t_{transfer} = 2 \cdot 20.38 + 0.09 = 40.85ms \; $$
